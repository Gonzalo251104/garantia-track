## User-facing change

Switching between Orders, Reception and Workshop keeps the current authorized screen visible until the fresh destination is ready. A compact status/progress line and an outlined destination replace the intermediate loading page. Navigation and sign-out stay available. Previous-page controls are inert during the transition, and focus moves to the destination when ready. Existing route scroll-to-top behavior is preserved.

This improves visual continuity; it does not establish lower network latency. Initial loads, reloads and access changes can still show connection guidance. Draft values stay in the retained DOM while waiting, with the existing discard behavior after leaving a screen. Cross-route draft saving and offline access are outside this release.

Implemented through PR #56, merged into develop at `1ea6a921cf79a79b868a7accbc6c8a191f916e7e`. No database migration, policy/permission change, SDK/dependency update, key lookup or paid service is required. Existing migrations remain deployed and compatible; do not replay them or run a blind database push.

## Access and lifecycle

Fresh workshop membership and scoped order reads remain on every route. Changed or missing membership clears the retained page before waiting for another workshop's data. Account/recovery changes remove it immediately; a current read error clears the view and shows existing retry guidance. Obsolete responses cannot replace or invalidate a newer destination. No private-data persistence or offline fallback is introduced.

Render-generation checks guard form, photo-recovery, image-loading and private-link callbacks while the old DOM is retained. Requests already submitted can finish on the server, but late callbacks cannot redirect navigation, report success in another view or update the active workshop identity. The enlarged-photo viewer still closes at navigation start. Private Storage/RLS, confirmed-photo immutability, existing QR/expiry and Vault references remain unchanged.
