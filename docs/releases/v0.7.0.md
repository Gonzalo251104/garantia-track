# v0.7.0

Release candidate prepared on 2026-11-04, America/Lima. Preparation does not publish a GitHub release, create a tag or deploy Sites. Public v0.6.0 remains at canonical main `e750525222a7ff8a58dd882fce14070484d7944a` until those separate steps complete.

## User-facing changes

After a successful signup without a session, **Revisa tu correo** replaces the small inline hint and cleared form. The focused heading, readable instructions and sign-in/different-email actions make the next step visible. The guidance stays neutral about account existence and does not claim email delivery. The original PKCE redirect, returned-session path and provider errors are preserved; an abandoned form cannot receive a late confirmation. Implemented through PR #43.

Order detail now has a dedicated **Cambiar estado** panel with four primary choices: **Recibido**, **En reparación**, **Listo para entregar** and **Entregado**. **Otros estados** retains En diagnóstico and Por aprobar; a current additional state starts selected and expanded. All six stored values and historical events remain valid. The shared `ready` label becomes Listo para entregar across the interface/receipt. Implemented through PR #44.

**Guardar estado** saves independently of the quote, internal note and public-message drafts. Selecting a radio does not write; saving the existing state is a no-op. Pending drafts remain on screen and are not implicitly saved, even if another form's quote is invalid. Saving quote/messages afterward retains the latest status/version. The original member/version-checked update RPC, field validation and event transaction remain authoritative. Confirmed success refreshes status/history without remounting the draft or photo controls. Busy/context guards and keyboard focus handling are retained.

No database migration, dependency update, Auth/SMTP setting, key rotation, Storage policy change, stored-state removal or tracking rotation is required. There is no automatic WhatsApp delivery or mandatory status-transition sequence. Navigation/loading, Taller settings, enlarged photos, Other equipment and broader typography changes are outside this release. Draft Vault recovery PR #26 remains excluded.

## Evidence and limits

- The feature heads passed lint, syntax checks, 72 tests and build. Registration tests cover neutral signup results, original request/session handling, provider errors and stale views. Status tests cover primary/additional states, persisted fields/events, no-op/duplicate/inactive writes, failures/context changes, focus and the actual SDK/versioned RPC over isolated HTTP. Release PR CI must pass again on its current head.
- Assisted browser checks used isolated loopback services and synthetic data, with no real signup or email delivery. Registration focus/return actions, independent status saving, invalid quote/draft preservation, later draft saving, reload, stale-version errors, radio keyboard selection and explicit demo persistence were checked. Inspected 320/390/900 px desktop-browser viewports had no horizontal overflow. These are contract/responsive checks, not physical Safari acceptance or a performance benchmark.
- The owner reported that an independent technician on iPhone 15/Safari completed fictional GT-1051 receipt/photo, reload, statuses/messages and PDF/private tracking without help on v0.6.0. That feedback motivated these changes; it does not accept the new v0.7.0 screens. Excel/paper is their current process, and interest was conditional on several concurrent repairs. No repeated-use, price or market-fit claim is made.
- Actual-session cross-workshop photo HTTP testing remains explicitly deferred and unverified. SMTP/external confirmation and password recovery, complete independent database/Auth/Vault/photo recovery, operating ownership/retention/support and any promised physical printing remain separate gates before real-customer data. Keep the pilot fictional.
