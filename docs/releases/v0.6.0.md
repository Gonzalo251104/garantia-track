# v0.6.0

Members can complete pending intake photos from a saved order after closing or reloading the original reception. Select the original image again for its pending slot and retry; the existing order, ready photos, status history and tracking capability are preserved. The intake error links to the saved order.

Missing evidence without a persisted reservation can also be completed, one image at a time, within the existing five-photo limit. Existing pending slots are completed before additional photos are offered. Ready objects cannot be overwritten. Recovery refreshes only photo metadata/gallery and preserves unsaved repair edits. Async responses are guarded by the originating view/account/workshop and the target must be ready before success is reported.

This release also includes the operator-only photo access guide/helper and anonymous known-photo HTTP checks already merged through PRs #37 and #38. They are not part of the public static deployment and do not certify actual-session nonmember access until that exercise is completed.

Validation: PR #39 passed lint, syntax checks, 62 tests and build. Local assisted browser checks left and reloaded a failed intake, encountered a second intentional failure, then recovered one photo while preserving an unsaved repair note. Fixture counters confirmed one order, reservation, object and initial event across three uploads. Inspected 320/900 px views had no horizontal overflow. These are local desktop/contract-fixture observations, separate from hosted or physical-device acceptance.
