# v0.9.0

Release candidate prepared on 2026-11-05, America/Lima. Public v0.8.0 remains at canonical main `c0a4a3e62595219b18beeca9380dfd8a1f1340a0`. Preparation does not merge main, create a tag or deploy Sites.

## User-facing change

Click, tap or keyboard-activate **Ampliar** on a saved-order intake photo to inspect it in a native modal dialog. The complete landscape/portrait image fits the available viewport without the thumbnail's crop. **Cerrar foto**, Escape and an outside-backdrop click close it; focus returns to the current thumbnail. The close target is at least 48 px high.

Opening/closing does not remount or submit the repair form, change status, save a draft or mutate photos. Existing demo-order photos use the same controls. Intake/upload previews, receipts and customer tracking remain outside this feature; customer tracking still does not display workshop photos. There is no carousel, download/share action or image transformation service.

Implemented through PR #53, merged into develop at `068e0ee64f1b2c80510c123249a5d4625b87f74c`. No new database migration, SDK/dependency update, permission/configuration change, key lookup or paid service is required. Existing v0.8.0 workshop settings and its deployed migration remain unchanged; do not replay that migration or run a blind CLI database push.

## Privacy and lifecycle

The viewer reuses the thumbnail's existing private image source. It does not sign another link, extend its five-minute lifetime or change the private bucket/RLS/member checks. Normal browser caching may reuse bytes or issue an image GET for the same URL; zero additional network traffic is not promised. The displayed image is the already stored/compressed file, not a reconstructed higher-resolution original.

Both images use no-referrer policy. Closing clears the enlarged source/callbacks and removes the dialog; current thumbnails retain their sources while the authorized order remains displayed. Navigation, authentication/recovery changes, sign-out and gallery replacement close the viewer. Render-generation and DOM attachment checks reject obsolete thumbnail events and late image callbacks. Errors stay generic and ask the operator to reopen the order to reload photos; no automatic capability refresh or write is introduced.

No image source is placed in a new route, persisted in new storage, copied to the clipboard or displayed in an error. This feature does not add stronger live revocation guarantees than the existing temporary capability model. Orders, confirmed photos, tracking hashes/expiry and Vault references are unchanged.
