# GarantiaTrack v0.4.0

Receipt QR codes can now be recovered after reload, in another tab or after signing in again, without invalidating existing tickets or extending their expiry.

- Recoverable capabilities are encrypted in Supabase Vault and returned only through workshop-membership-checked RPCs.
- Public customer tracking keeps its hash lookup, original URL format and minimal output allowlist.
- Per-order locks serialize recovery, first creation, import, rotation and revocation. Preparing an existing record never silently replaces it.
- Legacy QR import verifies the exact active token, preserving the original hash and expiry. The additive migration never invalidates older tickets.
- Expired/revoked links remain inactive until explicit renewal; raw tokens and decryption keys are not persisted in browser storage/configuration.

Validation: 41 tests, lint, syntax and build passed. PGlite authorization/lifecycle tests use a labeled Vault contract double. Separate live Supabase probes verified real encryption/decryption, scoped stable recovery and revocation with fixture changes rolled back. Anonymous receipt recovery/create/import were denied. Published reload, cross-tab and legacy adoption checks are recorded after deployment.

Older frontend signatures remain compatible. Frontend rollback must retain the additive migration and encrypted capabilities; key-preserving backup/restore is required when changing projects.
