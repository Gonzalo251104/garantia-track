## PR #2 corrections

1. Intake photos previously lived in a module-global array and were read after an awaited order request. Opening another intake while saving could associate the wrong batch with the first order. Photos are now form-local, captured before network waits, and submitted with stable request/photo identifiers. Form and identity guards prevent completed requests from writing into a different screen.
2. Order updates and link operations now retain their originating form, version and identity rather than editing whichever DOM is current when a response arrives. Creation RPCs transmit only intake metadata, not base64 photos or client event history.
3. The local initial migration version did not match the applied Supabase migration history. Its filename now uses the observed remote version 20261028060929; SQL is unchanged and was not reapplied.
4. CI now handles edited pull requests so changing the base triggers a new check run.

Added regression coverage for delayed intake requests, photo-batch isolation, metadata-only RPC payloads and explicit partial-upload errors. The suite now contains 22 passing test results. Existing tenant isolation, transaction, photo policy and token lifecycle tests remain intact.

PR #2 was retargeted from feature/navigable-prototype to develop after PR #1 merged. No application code was pushed directly to a permanent branch, and main is not part of this development integration. Supabase schema and existing QA records are unchanged by these review corrections.
